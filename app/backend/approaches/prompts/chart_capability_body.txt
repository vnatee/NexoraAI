
HOW TO GENERATE A CHART:
After your natural-language explanation, append a chart spec in EXACTLY this format:

```chart-spec
{
  "option": { ...Apache ECharts option object... },
  "height": 400
}
```

CRITICAL FORMAT RULES:
- You MUST wrap the JSON in ```chart-spec ... ``` code fence EVERY TIME. Do NOT output raw JSON without the fence.
- The opening fence must be exactly: ```chart-spec (three backticks followed by chart-spec)
- The closing fence must be exactly: ``` (three backticks alone on a line)
- Do NOT output the JSON outside of this fence under any circumstances.

EXAMPLE - Bar Chart:
```chart-spec
{
  "option": {
    "title": { "text": "Monthly Sales", "left": "center", "textStyle": { "fontSize": 16 } },
    "tooltip": { "trigger": "axis" },
    "legend": { "bottom": 0 },
    "grid": { "left": "3%", "right": "4%", "bottom": "15%", "containLabel": true },
    "xAxis": { "type": "category", "data": ["Jan", "Feb", "Mar", "Apr"] },
    "yAxis": { "type": "value" },
    "series": [
      { "name": "Sales", "type": "bar", "data": [120, 200, 150, 80], "itemStyle": { "color": "#5470c6", "borderRadius": [6, 6, 0, 0] } },
      { "name": "Target", "type": "bar", "data": [100, 180, 160, 90], "itemStyle": { "color": "#91cc75", "borderRadius": [6, 6, 0, 0] } }
    ]
  },
  "height": 400
}
```

EXAMPLE - Pie Comparison (2 pie charts stacked VERTICALLY for comparing two datasets):
IMPORTANT: When comparing 2+ pie/donut charts, ALWAYS stack them VERTICALLY (top/bottom), NEVER side by side (left/right). This prevents labels from overlapping and ensures each chart has enough space.
- Use `top` positions like "5%", "55%" for two charts
- Set `center` to `["50%", "28%"]` and `["50%", "75%"]` (vertical stacking)
- Set `radius` small enough: `["30%", "48%"]` so charts don't overlap
- Give each chart its own `title` using `top` offset
- Use a SINGLE shared `legend` at the very bottom
- height should be at least 700 for 2 charts, 1000 for 3 charts
```chart-spec
{
  "option": {
    "title": [
      { "text": "Market Share 2024", "left": "center", "top": "2%" },
      { "text": "Market Share 2025", "left": "center", "top": "51%" }
    ],
    "tooltip": { "trigger": "item", "formatter": "{b}: {c} ({d}%" },
    "legend": { "bottom": 10, "left": "center" },
    "series": [
      {
        "name": "2024",
        "type": "pie",
        "center": ["50%", "28%"],
        "radius": ["28%", "44%"],
        "itemStyle": { "borderRadius": 6, "borderColor": "#fff", "borderWidth": 2 },
        "label": { "formatter": "{b}: {d}%" },
        "data": [
          { "value": 40, "name": "Product A", "itemStyle": { "color": "#5470c6" } },
          { "value": 30, "name": "Product B", "itemStyle": { "color": "#91cc75" } },
          { "value": 20, "name": "Product C", "itemStyle": { "color": "#fac858" } },
          { "value": 10, "name": "Product D", "itemStyle": { "color": "#ee6666" } }
        ]
      },
      {
        "name": "2025",
        "type": "pie",

- "line" chart (กราฟเส้น): series type="line", NO areaStyle property at all.

CRITICAL 3D CHART FORMATTER RULE (applies to ALL ECharts-GL series: bar3D, line3D, scatter3D, surface):
- The string template parser in ECharts-GL (formatTpl) uses plain string `.replace()`. It only supports the plain tokens `{a}`, `{b}`, `{c}` where `{c}` expands to the FULL value array (e.g. `"0,0,18563"`). It does NOT support array indexing.
- Therefore NEVER use `"{c[0]}"`, `"{c[1]}"`, `"{c[2]}"`, `"{@[0]}"`, `"{@[1]}"`, `"{@[2]}"` in any 3D series `tooltip.formatter` or `label.formatter`. echarts-gl will render the literal text (e.g. users will see the string `{c[2]}` on screen) instead of the value.
- The ONLY safe options in a pure-JSON spec are:
  1. OMIT the `formatter` entirely — let echarts-gl use its built-in default tooltip, which automatically lists all dimensions (e.g. `- x: ... \n- y: ... \n- z: ...`). RECOMMENDED.
  2. Use a plain `"{a}"` or `"{b}"` token only (these work because they are single-value).
- This limitation does NOT apply to regular 2D ECharts charts (bar, line, pie, ...) — there `{c[2]}` / `{@[2]}` work fine via the core dataFormat mixin.

EXAMPLE - Surface Chart (Requires ECharts GL):
- Surface chart requires TRUE 2D grid data: z = f(x, y) — e.g. sales by product × time period.
- If the user's data is a simple 1D list (only one dimension), do NOT use surface. Use bar or line instead and explain why.
- Minimum data: 4×4 = 16 points covering all combinations of x and y values.
- Each data point: [x_value, y_value, z_value]
```chart-spec
{
  "option": {
    "title": { "text": "ยอดขายตาม Product × ปี", "left": "center" },
    "tooltip": {},

STRICT JSON & FORMATTING RULES:
- STRICT JSON ONLY: You MUST output PURE, VALID JSON only. NEVER output JavaScript functions, callbacks, arrow functions, or executable code (such as `function(params) { ... }` or `formatter: params => ...`). All keys and string values must be double-quoted.
- NO COMMENTS: Do NOT add any comments (// ... or /* ... */) inside the JSON. JSON does not support comments and they will break parsing.
- COLORING INDIVIDUAL BARS/ITEMS: To set different colors for individual bars or data points in a single series, do NOT use a callback function. Instead, use one of these two valid JSON patterns:
  1. Set a global color array at the root "option" level: `"color": ["#4caf50", "#f44336", "#ffeb3b"]`.
  2. Or specify each item in the series `"data"` array as an object with its own `"itemStyle"`:
     `"data": [ { "value": 120, "itemStyle": { "color": "#4caf50" } }, { "value": 145, "itemStyle": { "color": "#f44336" } } ]`.
- TOOLTIP/LABEL FORMATTERS: Use static string templates (e.g. `"{b}: {c} ({d}%)"`) instead of formatting functions.
